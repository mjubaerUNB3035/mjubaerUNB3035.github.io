WatchTower: AI SOC Analyst Platform

An all in one security platform that collects security events, raises alerts, judges them with AI, and tracks incidents, built as separate services that talk to each other through APIs.

  • Architecture: separate Python services (collector, ingest API, dashboard API, web dashboard) backed by PostgreSQL, all running in Docker
  • Event pipeline: collectors gather security events and store them in the database through the ingest API
  • Alert rules: a rules engine checks incoming events and raises alerts when patterns match
  • AI triage: each alert is judged by a local AI model (Ollama, llama3.1:8b), which gives a verdict, a confidence score, and a reason
  • Human review: a reviewer can accept or correct each verdict, and past corrections are fed back into future AI judgments, so the system learns from its mistakes
  • Incidents: confirmed alerts become incidents that can be tracked to closure
  • Scanner section: checks machines for open ports and risky services, stores every scan, and has the AI judge how risky each machine is
  • Phishing section: watches a mailbox automatically, runs a set of detection checks on every new email (fake sender, dangerous links, hidden links, fake attachments, failed authentication, pressure wording, and more), then gives an AI verdict with reasons
  • Testing: 34 automated tests covering the services

Zenith: Stock Breakout Detection System

A stock scanning system that marks stocks setting up for a breakout before the breakout happens, then watches whether the mark was right.

  • Marking rules: a stock is marked when its close sits within 5 percent below its prior 55 day high, with a 20 day range over 26 percent, 60 day momentum over 45 percent, RSI between 55 and 80, MACD rising and positive, and price above its 200 day average
  • Buying volume rules: 10 day average volume at least equal to the prior 20 day average, plus at least 3 accumulation days in the last 20 days (an up day closing on at least 1.2 times the 50 day average volume)
  • Forward testing: every mark is written to a ledger and measured at 40 and 60 days against a strict test: a real break must reach plus 30 percent before ever dipping minus 10 percent
  • Results so far: 112 marks placed, 82 measured, 62 true breaks, 48 big runs, 36 clean runs
  • Paper trading: a paper portfolio tracks the strategy on live market data, with the marker running on a weekday evening schedule

Repo Repair Agent

An autonomous agent that reads a real software bug report, finds the faulty code, writes a fix, and proves the fix by running the project's tests.

  • Framework: built with LangGraph as a single agent loop that decides one action at a time
  • Dataset: real bug fixing tasks from the SWE-bench Lite dataset on Hugging Face (princeton-nlp/SWE-bench_Lite)
  • Agent tools: code search, file reading, patch writing inside a Docker sandbox, and a test runner, so the agent never touches the real machine
  • Retrieval (RAG): repository code is split into chunks, embedded with a local model (nomic-embed-text through Ollama), and retrieved by meaning using cosine similarity, so the agent reads only the relevant code instead of whole files
  • Tracing: every action the agent takes is logged, so a full run can be replayed and checked step by step
  • Pilot test: the agent is being measured on a fixed pilot of 20 tasks, with pass rules set in advance: at least 4 tasks resolved, zero regressions on tests that already passed, and full traces for every run
